### Fixed

- Phase 1 Milestone 8 course rendering: the HUD's full-viewport root border used an opaque brush, masking the gray-box world behind the metric overlay. The root is now transparent and only the compact metrics panel is translucent. The oval spline was also a non-rendering transform guide and the boat-side camera could not frame the route; the gray-box actor now creates visible spline-mesh edge segments and uses an elevated fixed overview camera. `UCourseSubsystem` is now a world subsystem, so it owns the rendered world's course actor and camera instead of depending on a game-instance world lookup during startup; HUD creation explicitly activates that presentation first. The actor keeps its engine primitive meshes/material as hard references so they are retained in a cooked package. Automation coverage asserts the edge segment count and overview framing. Packaged simulator verification remains required.
- Phase 1 Milestone 10 review fixes: a development object upload now requires a finalized local session; completion rejects malformed or inconsistent metadata and verifies the stored object size; the worker bounds Zstandard expansion and rejects a non-`SessionObject` envelope; API request timeouts are bounded.
- Phase 1 Milestone 7 code-review follow-ups: `FRealDeviceController` now holds PM5 metric samples back from a new session after an End mid-row until the PM5 reports the row stopped (`IsAwaitingRowStop()`), so one physical workout is not journaled twice (the pm5-tui driver already did this); Connect-panel clicks select a PM5 by a stable per-candidate token (`FDeviceCandidate::Token`, `SelectByToken`, `SelectDeviceByToken`) instead of list position, which re-sorts by signal strength; plus the earlier review fixes (Hidden instead of Collapsed panel, app-data path under `~/Library/Application Support/dev.virtualrowing.app`, recovery scan skipped when the transport is unavailable, `MachineInfo` replayed into later sessions, failed discovery start shown as Problem, panel focus cue and generation). Covered by new `real_device_controller_tests` and `device_connector_tests` cases; the Unreal module was compiled (`make unreal-smoke`) but not run or exercised with a real PM5.
- Phase 1 Milestone 7: `ScanAndRecover` reports `RecoveredAfterUncleanExit` on every scan after the first recovery (by design), so a "recovered a session" notice would show on every launch; `FLocalDataRecoveryReport` gained `NewlyRecoveredSessionCount`, which is non-zero only on the scan that records the recovery. The app notice and the `pm5-tui` journal driver's banner use it.
- Phase 1 Milestone 6: the five findings deferred from Milestones 4 and 5 — the real adapter's `Ready`-before-`ConnectionRestored` order, `CreateSession` retry, a failed `WriteSummary` commit wedging the writer, per-session summary revisions, and the `pm5-tui` journal driver's event polling, mid-row End Session split and missing `CapabilityObserved`. See [06-milestone-6-hardening-and-refactor.md](06-milestone-6-hardening-and-refactor.md).
- Phase 1 Milestone 5 code-review fixes: the simulator pump no longer replays a long pause or stall into the machine's bounded queue (virtual-time step capped at 1 s); the HUD is not re-created every frame when it cannot be added to the viewport; the display model handles a device `WaitingToBegin` and a disconnect before any sample; `-NativeLinkageProbe` returns `false` instead of throwing and cleans up its SQLite sidecars; `make unreal-shipping` runs `make native-app` first. Defects found in Milestone 4 code (`Ready`/`Restored` ordering with the real adapter, no `CreateSession` retry, `WriteSummary` commit failure, per-sink summary revisions, `pm5-tui` `Ingest`/`Tick` and End Session behavior) are recorded in [05-milestone-5-unreal-hud.md](05-milestone-5-unreal-hud.md) for the real-device milestone and not fixed here.
- Phase 1 Milestone 3 second review pass: one `FSqliteConnection::InTransaction` helper replaces five hand-copied begin/commit/rollback blocks (recovery's `DeleteChunk` had been missed and could leave a transaction open); a failed `COMMIT` on a staged chunk/event/summary now keeps the stage so the caller can retry; `ScanAndRecover` examines every session in `journal_events` (not just the last with chunks) and ends a `sessions` row whose terminal event committed before a crash; `UpdateSessionState` rejects leaving `Ended`; journal-event payloads are sealed when a cipher is configured; `sessions` matching in recovery is a direct parsed-id `UPDATE` instead of a full scan; `FCryptoKitBlobCipher` zeroes its key on destruction and the Swift shim no longer copies the key through `Data`.
- Phase 1 Milestone 3 review findings: writer transactions now roll back on failure (a failed `Seal` previously wedged the writer); the Keychain create-race retry is bounded; schema migrations are race-safe with a busy timeout; `ReadSampleChunks` with a cipher rejects plaintext/unknown codecs; `session_summaries`/`cloud_links` reference `sessions`; `ScanAndRecover` ends the open `sessions` row; the CryptoKit end-to-end test now covers summaries.
